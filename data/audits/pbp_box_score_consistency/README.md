# PBP vs. official box-score consistency audit

**Question:** if we reconstruct a team's game statistics purely from CFBD `/plays`,
how often does that reconstruction match CFBD's own official `/games/teams`
box score, and exactly where/why does it differ?

Generated by `scripts/audit_pbp_box_score_consistency.py`. This audit does
not modify `data/canonical`, does not touch production metrics (APR,
ratings, EPA, predictions, refresh behavior), and does not change any
pipeline module. Two production-code fixes are **proposed and quantified**
below but were **not applied** -- see "Known bugs" and "Recommended next
steps."

## Populations audited

| Population | Team-games | Games | With box score | FBS-vs-FBS | FBS-vs-other |
|---|--:|--:|--:|--:|--:|
| **Primary: 2026, every completed game on disk** (weeks 1-2 regular; week 3+ not yet played as of 2026-09-19) | 372 | 186 | 372 (100%) | 202 | 170 |
| **Sanity sample: 2025, weeks 1, 2, 7, 8, 14, 15** | 670 | 335 | 670 (100%) | 670 | 0 |

No games were dropped for being FBS-vs-FCS; classification is reported
separately per team-game in `team_game_differences.csv`.

## Three layers compared

1. **`raw`** -- CFBD `/plays` classified only by CFBD's own `playType` label
   (a direct 1:1 reading of `canonical/play_types.py`'s static table, not an
   invented rule). Uses raw `yardsGained`. No no-play exclusion, no
   drive-ownership correction, no text-inference recovery of swallowed play
   types. This is "take `/plays` completely at face value."
2. **`canonical`** -- the real PRIME pipeline: `normalize_play` +
   `promote_partition_yardage` (yards-v1) + `correct_partition_drive_ownership`
   (drive-ownership-v1), plus one audit-added rule (text-inference recovery
   of fumble/safety-swallowed play types -- see below). Excludes no-play
   context plays from counts.
3. **`official`** -- CFBD `/games/teams`, parsed with the *exact* parser
   already in `scripts/export_team_game_advanced.py`
   (`BOX_SCORE_VERSION = "cfbd-games-teams-v1"`). This audit does not
   reimplement box-score parsing.

## Sack/dropback convention -- resolved empirically, not assumed

CFBD's official box score could plausibly file a sack as a rushing loss
(`sackAsRush`) or as a passing loss (`sackAsPass`, i.e. a "dropback"). Both
were computed for every team-game and scored against the real box score
(`summary.json` → `sackConvention`):

| Statistic | `sackAsRush` exact-match | `sackAsPass` exact-match |
|---|--:|--:|
| rush_attempts | 77.7% | 16.4% |
| rush_yards | 64.0% | 15.3% |
| pass_attempts | 59.9% | 24.5% |
| net_pass_yards | 86.0% | 18.8% |

**`sackAsRush` wins decisively on every statistic.** CFBD's official box
score follows the traditional NCAA convention: a sack is a rushing play with
a loss, not a pass attempt. This directly contradicts this repo's existing
analytics convention (`analytics/dropbacks.py`, `analytics/basic_yardage_team_metrics.py`),
which counts a sack as a **dropback** (pass-side). That is a legitimate,
intentional definition difference for EPA/success-rate purposes (a sack is
still a "pass play" from an efficiency-modeling standpoint), but it must
**never** be presented as an official rushing/passing-attempt count. This
audit's "reconstructable" numbers below all use the box-score-matching
`sackAsRush` convention.

### Game-level integrity

| | Every core stat matches | ≥1 mismatch | Major mismatch* |
|---|--:|--:|--:|
| raw layer | 13.4% | 86.6% | 44.9% |
| canonical layer | 23.4% | 76.6% | 25.8% |

\* **Major mismatch** is a fixed, pre-declared threshold per statistic
(`MAJOR_MISMATCH_THRESHOLDS` in the script), e.g. >2 plays, >10 yards, >1
turnover -- not a tolerance band chosen after the fact to make results look
better. A team-game with only off-by-one counting noise on a single
statistic is *not* a major mismatch; one with a double-digit yardage error
or a wrong turnover count is.

**Read this correctly:** "every core stat matches" is a strict AND across
11 statistics, so even a 95%-accurate-per-statistic pipeline would show a
low all-match rate here (0.95^11 ≈ 57%) purely from independent noise
across statistics -- it is not itself evidence of an 87% failure rate. The
per-statistic table above is the primary signal; game-level integrity is a
secondary, stricter view.

## Known bugs found and quantified (not fixed in production)

### 1. Fumble/safety plays swallow the underlying rush/sack/pass identity (source-side; recoverable by text)

CFBD's `/plays` feed reclassifies the **entire snap's** `playType` to
`Fumble Recovery (Own)`, `Fumble Recovery (Opponent)`, `Fumble Return
Touchdown`, or `Safety` whenever a fumble or safety occurs -- `Rush`,
`Sack`, and `Pass Reception` all disappear from the structured `playType`
field. The underlying play survives only in free-text `playText`
(e.g. `"...sacked for loss of 9 yards... fumble by J.Craig recovered by
UNC..."` filed under `playType: "Fumble Recovery (Own)"`; a 31-yard-loss
rush filed under `playType: "Safety"`). Because `canonical/play_types.py`
gives every one of these subtypes `is_scrimmage=False, is_offensive_play=False`
(except bare `"Fumble"`), the underlying rush/sack/completion was being
**dropped entirely** from rush/pass/sack counting -- not misclassified,
just gone.

**Exact example:** game `401856766` (TCU @ North Carolina, 2026 week 1),
TCU. Structured-only reconstruction: 34 rush + 2 sacks = 36 rush attempts
vs. official 39 -- missing exactly 3: one `Safety` row (a 31-yard-loss rush),
one `FUMBLE_RECOVERY_OWN` row that was actually a sack, one
`FUMBLE_RECOVERY_OWN` row that was actually a rush.

This audit adds a text-inference rule (`_text_inferred_subtype` in the
script) that recovers the underlying type from `playText` for these five
subtypes (`FUMBLE`, `FUMBLE_RECOVERY_OWN`, `FUMBLE_RECOVERY_OPPONENT`,
`FUMBLE_RETURN_TD`, `SAFETY`) via simple, ordered regex matching (`sacked` →
SACK, `pass complete` → completion, `pass incomplete` → incompletion, `rush`
→ RUSH). Effect, measured on the 2026 primary population (before → after):

| Statistic | Before | After |
|---|--:|--:|
| rush_attempts | 38.2% | 77.7% |
| rush_yards | 36.8% | 64.0% |
| pass_attempts | 52.2% | 59.9% |
| net_pass_yards | 76.9% | 86.0% |
| total_plays | 22.6% | 47.3% |
| total_yards | 29.8% | 55.6% |

**205/372 team-games (55%)** in the primary population had at least one
play affected by this. This is the single largest driver of rush/pass/yards
mismatch in the corpus, and it is entirely fixable from information already
in `/plays` -- CFBD's structured field is simply incomplete, not wrong.

**Affects:** our own canonicalization pipeline, specifically
`canonical/play_types.py`'s taxonomy, which treats `FUMBLE_*`/`SAFETY` as
disjoint from `SCRIMMAGE` instead of as a modifier on top of it.

### 2. Turnovers-v1's no-play signal is scoped to the whole drive, not the turnover play (our pipeline; production bug)

`cfb_analytics/analytics/turnover_forensics.py::classify_drive_turnover_from_plays`
(used by the **production** `turnovers-v1` module,
`cfb_analytics/analytics/turnovers.py`) computes its no-play signal as "does
*any* play in this drive have `hasNoPlayContext`?" If a drive has an
unrelated no-play penalty anywhere in it (e.g. a 1st-down false start) and
later, on a completely different snap, ends in an interception or lost
fumble, the whole drive is misclassified `MODIFIED_CONTEXT_REVIEW` and the
turnover is **silently excluded** -- not double-counted, not miscounted,
just dropped.

**Exact example:** game `401868241` (West Georgia @ Arkansas State, 2026
week 1), drive `40186824110`: 3 unrelated false-start penalties on downs 1-3,
then a clean `Fumble Return Touchdown` on a later snap. Production
classifies this drive `MODIFIED_CONTEXT_REVIEW` and drops the turnover
entirely; West Georgia's canonical turnover count for this game came out
**0** against an official box score of **4**.

**Quantified corpus-wide** (2026 weeks 1-2): of 114
`MODIFIED_CONTEXT_REVIEW` exclusions, **112 (98%)** have the no-play penalty
on a *different* play than the turnover signal (false positive); only 2
(2%) are genuine same-play nullifications that should stay excluded. This
audit's `classify_drive_turnover_scoped_from_plays` (candidate fix) scopes
the no-play check to the turnover-signal play itself. Effect, measured on
the 2026 primary population:

| Statistic | Before (turnovers-v1) | After (scoped fix) |
|---|--:|--:|
| interceptions | 78.8% | 90.6% |
| fumbles_lost | 66.7% | 72.3% |
| turnovers | 51.9% | 65.9% |

**Affects:** production code directly
(`cfb_analytics/analytics/turnover_forensics.py`), and therefore every
downstream consumer of `turnovers-v1`/`havoc-v1` turnover counts (turnover
margin, turnover EPA value in `exploratory_turnovers_propagation_cli.py`,
Havoc's turnover component).

### 3. Duplicate play records (source-side; CFBD data quality)

Some games in `/plays` contain literal duplicate rows: identical
`driveId`, `offense`, `defense`, `down`, `distance`, `playText`, **and**
`wallclock` timestamp, but a different play `id`. The existing raw-integrity
check (`raw/audit.py::audit_partition`, `unique_play_ids`) only verifies
`id` uniqueness and therefore cannot catch this -- a duplicate with a fresh
`id` passes that check trivially.

Measured with `duplicate_play_ids()` (requiring driveId+wallclock+content
match, not text alone -- see caution below):

| Population | Games affected | Excess duplicate rows | % of all rows |
|---|--:|--:|--:|
| 2026, weeks 1-2 | 0 / 186 (0%) | 0 | 0.00% |
| 2025 sample (wks 1,2,7,8,14,15) | 65 / 335 (19.4%) | 111 | 0.19% |

Removing these duplicates before reconstruction had **negligible aggregate
effect** on the sampled population (differences within noise; see
`summary.json` → `candidateDuplicatePlayFix`) -- the affected rows are
mostly non-scrimmage (kickoffs, timeouts) or already excluded contexts. It
is real and worth deduplicating on principle, but it is not a major driver
of the rush/pass/yards mismatch rate.

**Caution on methodology:** an early, looser duplicate-detection attempt
(matching on `offense`/`down`/`distance`/`playText` only, without
`driveId`/`wallclock`) found a much larger false "duplicate" rate, because
generic play descriptions (e.g. "run for 3 yds") legitimately recur many
times in a single run-heavy game on genuinely different downs. That looser
key is *not* used in the shipped script or the numbers above -- see
`test_duplicate_play_ids_does_not_flag_coincidentally_identical_text`.

### 4. One-off: incorrect offense-field attribution (source-side; documented, not corrected)

Game `401867796` (LSU @ Louisiana Tech, 2026 week 2): one
`FUMBLE_RECOVERY_OPPONENT` play's `offense` field reads `LSU`, but the
`playText` ("S.Leavitt pass complete... fumbled... recovered by LAT")
describes a Louisiana Tech snap recovered by Louisiana Tech itself. This
misattributes one pass-completion event to the wrong team. This is a single
anecdotal occurrence in the sampled population, not corrected here per
instructions not to patch broad rules from one example -- flagged for
awareness, not action.

### 5. One severe outlier game, likely provider-side (documented, not diagnosed further)

Game `401761632` (Marshall @ Texas State, double-overtime, 2025 week 8):
canonical reconstruction gives Marshall 68 rush attempts against an
official 48 (+20); Texas State 62 against 44 (+18). This is far outside the
normal residual-noise range seen everywhere else in the corpus. The
duplicate-play check above does **not** explain it (only 0-1 rows removed
per team). The most plausible explanation given the evidence -- identical
generic play text recurring at very different wallclock timestamps and
drives -- is a provider-side data quality problem specific to this game
(possibly two overlapping charting feeds), not a general pattern found
elsewhere in either sampled season. Recommend a one-off support ticket to
CFBD for this specific `gameId` rather than a pipeline change.

## Root-cause frequency (2026 primary; canonical layer)

| Root cause | Mismatches | Team-games affected |
|---|--:|--:|
| fumble_or_safety_swallows_scrimmage_type | 666 | 205 |
| kneel_accounting (tag co-occurrence -- see caution below) | 362 | 149 |
| no_play_penalty | 239 | 99 |
| sack_accounting | 113 | 40 |
| spike_accounting | 35 | 15 |
| two_point_attempt | 3 | 1 |
| accepted_or_declined_penalty | 1 | 1 |
| **unknown** | **0** | **0** |

**Caution on `kneel_accounting`:** this label is assigned whenever a
mismatched team-game's plays merely *contain* a kneel, which is common and
does not by itself establish causation. A direct exclusion experiment
(remove all kneel-tagged rush attempts and recheck) improved the match for
only **5 of 116** kneel-containing team-games -- i.e. kneels are correctly
counted as rush attempts in the vast majority of cases, and this label
mostly reflects incidental co-occurrence with the real cause (usually
fumble/safety-swallowing), not kneel mishandling itself. Kneels should
**not** be excluded from rush attempts. The same caution applies in
principle to `no_play_penalty`, `sack_accounting`, and `spike_accounting`:
these are the current best-available per-mismatch labels (checked in the
priority order duplicate → fumble/safety-swallow → sack → kneel/spike/
two-point → no-play/accepted-penalty → turnover-specific → unknown), but
only the fumble/safety-swallow and turnover-no-play-scope causes above were
independently validated with a before/after corpus-wide experiment. Treat
the frequency table as a triage aid, not a certified causal decomposition.

**Zero "unknown" mismatches** in both the 2026 primary and 2025 sanity
populations: every mismatch found a candidate explanation, even if (per the
caution above) not every label is independently proven causal.

## Source discrepancy vs. our-pipeline discrepancy (Phase 8)

| Cause | Layer | Fixable from `/plays` alone? |
|---|---|---|
| Fumble/safety swallows scrimmage-play identity | Both raw and canonical (structural taxonomy gap) | **Yes** -- text-inference rule recovers it; see fix #1 |
| Turnover no-play scoped to whole drive | **Canonical only** -- this is our own module's bug, not a raw-data limitation | **Yes** -- scoped check; see fix #2 |
| Duplicate play records | Raw source data quality | Partially -- detectable and removable, small effect |
| Incorrect offense-field attribution (LSU example) | Raw source data quality | No general fix from one example |
| Marshall/Texas State outlier game | Raw source data quality (likely provider-side) | No -- needs CFBD support escalation |
| Sack = dropback (not rush) in existing `analytics/dropbacks.py` | Intentional definitional choice for EPA, **not a bug** -- but must never be presented as the official rush/pass attempt count | N/A |

**Bottom line:** the two biggest, most impactful problems (#1 and #2 above)
are **fixable from information CFBD already provides** in `/plays` --
neither requires CFBD to publish better data. #2 in particular is a genuine
**production code bug** in `turnovers-v1`, independent of any CFBD data
quality issue.

## Advanced game stats cross-check (Phase 9)

Added `CfbdClient.game_advanced_stats()` (`/stats/game/advanced`,
`excludeGarbageTime=false`). Sample pulled for 2026 weeks 1-2, saved to
`advanced_stats_sample/week{01,02}.json` (not committed to `data/raw` --
this is audit-only evidence, ~2 API calls).

- **`offense.plays` vs. our canonical `total_plays`:** matched 370/372
  team-games by (gameId, team). Mean difference **+1.95** (CFBD's advanced
  count is higher), median exactly **+2**, low spread (stdev 1.19), exact
  match only 9.5%. This is a **consistent, near-constant offset**, not
  random noise -- CFBD's advanced-stats play denominator includes ~2
  plays/game that our box-score-oriented `total_plays` (rush + pass
  attempts, excluding two-point conversions) deliberately excludes. The
  most likely candidates, given what `total_plays` excludes by design, are
  two-point conversion attempts and/or defensive-penalty automatic first
  downs with no snap -- not independently confirmed play-by-play in this
  audit; flagged as a follow-up rather than asserted.
- **`offense.drives` vs. our `validatedPossessions`:** 85.4% exact match,
  mean difference +0.12 -- close agreement, confirming `validatedPossessions`
  is a solid (if not perfect) proxy for CFBD's own drive count.
- **PPA / success rate:** not compared quantitatively against our EPA/success
  rate in this audit. Per the instructions, equivalence should not be
  assumed -- this repo's own prior research
  (`analytics/epa_eligibility_audit.py`, `analytics/success.py`) already
  establishes that our EPA/success populations use different play-eligibility
  rules than CFBD's PPA. A rigorous magnitude-level PPA-vs-EPA reconciliation
  is a separate, larger effort and is out of scope for this box-score-focused
  audit.

## Reconstructability classification (Phase 2)

See `summary.json` → `reconstructability` for the full table with reasons.
Short version:

- **EXACTLY_RECONSTRUCTABLE:** `points` (direct passthrough of CFBD's own
  running score field), `completions` (never moves between conventions),
  `total_plays` and `total_yards` (convention-independent -- sack yardage
  moves between rush/pass buckets but never leaves the total).
- **RECONSTRUCTABLE_WITH_RULES:** `rush_attempts`, `rush_yards`,
  `pass_attempts`, `net_pass_yards` (need the empirically-resolved
  `sackAsRush` convention and the text-inference fix), `turnovers`,
  `interceptions`, `fumbles_lost` (need the validated drive-level classifier
  plus the no-play-scope fix).
- **APPROXIMATELY_RECONSTRUCTABLE:** `third_down_attempts`/`conversions`,
  `fourth_down_attempts`/`conversions` -- a distance/yards-gained structural
  heuristic, consistent with this repo's own prior finding
  (`analytics/first_down_generation_final_residual_forensics.py`) that this
  exact signal has unexplained residuals. Not locked as a definition.
- **NOT_RELIABLY_RECONSTRUCTABLE:** penalty **team attribution**. CFBD's
  `playText` names the penalized team only by abbreviation (e.g. "PENALTY
  NDSU Holding"), with no structured field and no abbreviation→team mapping
  in `/plays`; enforcement text is highly variable (yardage sometimes
  reflects the penalty, sometimes the down). Aggregate two-team-combined
  penalty *counts* are plausible; per-team attribution is not, and was not
  attempted here. Possession time was not attempted (not present per-play
  in `/plays`; it is a `/games/teams`-only official field with no reliable
  PBP analog).

## Impact on APR / ratings / EPA / predictions

**None from this audit.** No production module was changed. The findings
above have a plausible, but *not yet measured*, path to affecting:

- Turnover margin, turnover EPA value, and Havoc's turnover component
  (fix #2 -- production bug, independent of CFBD data quality).
- Any downstream metric that sums canonical `analyticsYardsGained` over
  rush/pass buckets by convention (fix #1 -- but note EPA/success-rate
  already use their own eligibility rules, e.g. `dropbacks.py` intentionally
  treats a sack as a pass play for efficiency purposes, which is legitimate
  and should **not** be changed to match the box-score convention).

Quantifying the actual APR/rating/EPA delta from fix #2 requires re-running
the full historical corpus through `turnovers-v1` with the scoped fix and
diffing team-season turnover margins and EPA turnover-value -- not done
here, flagged as the concrete next step if a production fix is approved.

## Recommended next steps

1. **Fix the turnovers-v1 no-play scoping bug** (`turnover_forensics.py::classify_drive_turnover_from_plays`).
   This is a real production bug, not a CFBD limitation, with a validated
   98%-false-positive rate on its current exclusion logic and a
   quantified, substantial accuracy improvement (turnovers 51.9%→65.9%,
   interceptions 78.8%→90.6%). Before shipping: re-run the existing
   `turnover_forensics`/`turnovers`/`havoc` test suites against the scoped
   version, and re-check the 2 genuine same-play nullification cases found
   in this sample still behave correctly (both do, per this audit's tests).
2. **Add the fumble/safety text-inference rule to `canonical/plays.py` or
   `canonical/play_types.py`** so rush/pass/sack counts are additive across
   the taxonomy rather than losing information whenever a fumble or safety
   occurs. Affects any consumer of `isScrimmagePlay`/`isOffensivePlay` for
   these five subtypes -- audit downstream before shipping (EPA, Success
   Rate, and Havoc all read these flags).
3. **Do not** change `analytics/dropbacks.py`'s sack-as-dropback convention
   -- it's a legitimate, intentional EPA-population choice, separate from
   the official box-score convention confirmed here.
4. **Do not** exclude kneels or spikes anywhere -- both are already handled
   correctly; this audit affirmatively disproves the "kneels are
   mishandled" hypothesis with a direct exclusion experiment.
5. Consider adding a duplicate-play check (`driveId` + `wallclock` +
   content) to `raw/audit.py`'s partition integrity checks -- low
   prevalence and low impact today, but the existing `unique_play_ids`
   check cannot see it at all, and 2025's rate (19.4% of sampled games) is
   materially higher than 2026's (0%).
6. File the Marshall/Texas State (`401761632`) anomaly with CFBD directly;
   don't build pipeline logic around a single outlier.
7. Before any production change: re-run this audit's full 2026 + a larger
   2025/2024/2023 sample post-fix to confirm the improvement generalizes
   and doesn't regress anything, then measure the actual downstream
   APR/EPA/turnover-margin delta before considering it "done."

## Trustworthiness verdict

Core traditional box-score counting stats reconstructed from raw
`/plays` **without any fixes** are unreliable enough that they should
never be substituted for the official `/games/teams` box score -- which
this repo already correctly avoids (`BOX_SCORE_VERSION =
"cfbd-games-teams-v1"`, `export_team_game_advanced.py`'s explicit
"never substitute a derived/PBP metric for an official box-score field"
policy). That policy is validated and should stay exactly as it is.

The PBP-**derived analytics** built on top of canonical plays (EPA, Success
Rate, Havoc, drives) rest on a different population (scrimmage plays
generally, not a literal rush/pass attempt count) and are not directly
invalidated by the box-score mismatches found here -- except where they
depend on the specific mechanisms in bugs #1 and #2, which do plausibly
leak into turnover-derived metrics (Havoc's turnover component, turnover
EPA value) until fixed.
